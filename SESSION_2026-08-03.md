## 3. Defects found while rebuilding

**The build script ignored the new clips entirely.** `collect_reference_clips`
uses a hardcoded folder list with a non-recursive glob. The first rebuild
reported success and added nothing; it was caught by checking the row counts
rather than by any error. Now recursive, with `C_pogonias` in the list.

**The new confuser clips had the wrong window convention.** They are review
exports, cut from `max(0, start - 0.5)`, but arrived tagged `reference:`, which
sends them through the loudest-window crop instead. The packer's own docstring
warns that getting this wrong "would quietly cost accuracy that no test would
catch". They are now tagged `colobus_field_fp`, which is already in
`PADDED_SOURCES`.

**`pack_v13_images.py` had no atomic write.** The index CSV is written after the
image array, so a run killed part-way left a new half-written image file beside
the *previous* index. The two have different row counts and the index carries the
row number that addresses the array, so every row read afterwards would have been
the wrong clip. Both outputs now build under `.partial` and swap in together.

**`os.replace` on the feature cache failed on Windows.** The atomic-rename fix
added to `feature_cache()` in a previous session opens the stale cache as a
memmap to check its row count and never closes it, and Windows will not replace a
file that has an open handle. This only reaches that branch when the row count
actually changes, which had never happened before a class was added. The memmap
is now closed explicitly.

## 4. The headline number was fitted on the test fold

This is the important one. `score_fold` computed the matched-recall threshold as

```python
call_scores = np.sort(score[is_call])   # the held-out station's own labels
t_match = float(call_scores[...])
kc_m, kf_m = at(t_match, require_top=False)
```

`is_call` is the held-out station's human review. The threshold is therefore
chosen with the answers in hand, and `require_top=False` additionally drops the
grouped-argmax rule that deployment uses, which `fires_as_cernic` in the same
file documents as biasing results generously.

So `0.6953 -> 0.9340` compared V12 at its real operating point against V13 at an
oracle threshold with the decision rule removed. Across the sixteen folds those
thresholds ranged from **0.004 to 0.9964**. There is no single number a reader
could deploy.

`fold_masks` now returns a third mask, and `score_fold` reports `loso_*` columns:
the threshold fitted on the other fifteen stations, applied to the held-out one,
`require_top` left on. The recall it achieves is measured rather than imposed.
The `matched_*` columns are kept, with the docstring now stating they are an
upper bound on ranking quality and not an operating point.

First four folds, five-class model:

| station | deployed | oracle | **LOSO-fitted** | recall at the fitted threshold |
|---|---|---|---|---|
| IPA4ST | 0.6947 | 0.9886 | **1.0000** | 0.890 |
| IPA7ST | 0.6053 | 0.7097 | **0.7612** | 0.739 |
| IPA1ST | 0.4368 | 0.8915 | **0.9881** | 0.686 |
| IPA11ST | 0.4516 | 0.5405 | **0.5862** | 0.810 |

The fitted threshold gives *higher* precision than the oracle one on all four,
because it is more conservative: it buys precision with recall the oracle
threshold was forbidden from spending. The paper's "at matched 95 % recall"
framing has to be rewritten around this, since recall is now an outcome.

## 5. Two checks that came back negative, and one that came back small

**The pogonias clips are library audio, and an earlier reading here was wrong.**
Corrected 2026-08-04 after the expert confirmed they were cut from a sound
library, not from the deployment. A noise-floor comparison run the night before
had been read as showing they were IPA-channel field audio; it does not support
that. The numbers were 0.598 against raw IPA and 0.635 against the archival
colobus library, which are the same to within the noise of the measure. The
0.010 floor that made the IPA reading look decisive came from the reverse
comparison and is not symmetric with the other two. The fingerprint result that
found no match against anything this repository exported was the reliable one.

Two consequences. There is no leakage: library clips belong to no station, so the
empty `station` and `possible_stations` fields are the correct encoding, the same
one the 172 archival `Colobus_guereza` clips already carry. And the ablation now
has a cleaner explanation than "leakage flattered it": a field confusion was
being treated with archival recordings of the confuser, which is the same
archival-to-field gap the Colobus class already suffers from.

**Station recovery from audio: does not work.** Attempted while the clips were
still believed to be deployment audio, and validated first on 200
`Colobus_confuser` clips whose station is known: **top-1 accuracy 0.190 against a
chance baseline of 0.250**, worse than guessing. Noise floor distinguishes
recorders, not stations within one deployment of identical recorders. Nothing was
written. The result is retained because it bounds what this kind of attribution
can do for any future batch that does arrive without provenance.

**The pogonias clips are not re-exports of anything scored here.** Fingerprint
matching against all 6 189 reviewed Cernic detections, 253 Colobus detections and
4 344 auto-flagged negatives: best match anywhere **0.7204**, and 0.5944 against
the reviewed set. Identical audio would score above 0.98. The first version of
this check reported zero matches for the wrong reason, sliding the shorter
fingerprint through the longer one, which tests exactly one alignment when both
are 3.0 s; it now pads by 1.5 s either side and reports the score distribution
rather than a count over a threshold.

**Fold independence is better than the five-minute figure suggests.** For every
confirmed call, whether a confirmed call of the same species exists at a
*different* station within a window:

| window | other station | same station (control) |
|---|---|---|
| +/- 2 s | **0.025** | 0.935 |
| +/- 5 s | **0.050** | 0.951 |
| +/- 15 s | 0.092 | 0.966 |
| +/- 30 s | 0.143 | 0.982 |
| +/- 300 s | 0.580 | 0.992 |

A bout lasts seconds, so the tight windows are the relevant ones: same-event
leakage into a held-out fold is bounded at about 5 %, not the 52 % a
five-minute binning implies. The same-station control at 0.935 confirms the
measure detects real bout structure. Neighbouring pairs, if a
leave-one-neighbourhood-out variant is ever wanted: IPA17ST/IPA8ST (224),
IPA1ST/IPA20ST (138), IPA19ST/IPA1ST (116), IPA16ST/IPA20ST (104).

# Addendum, 2026-08-05: a defect in section 2, and what changed after fixing it

## The 253 clips were already in the dataset

Section 2 above says `Colobus_confuser` went from 654 to 907 by adding the 253
reviewed deployment detections. That is wrong in a way that mattered.
`collect_colobus_detections()` in the build script had been collecting those same
253 files since before this session, labelled `Background`, with a proven station
and the correct padded-window source tag. Copying them into
`data/species/Colobus_confuser/` made the build script collect them a second
time, so the same audio entered training twice under two labels that disagree.

Both labels route to Background through `config.DETECTION_GROUPS`, so nothing the
pipeline reports was affected, but the model was given contradictory supervision
on 253 of 31 424 rows.

The fix was one word in `collect_colobus_detections()`: label them
`Colobus_confuser` rather than `Background`, which is the change that was wanted
all along. The copied folders, the recursive glob and the source-tag branch added
here were all unnecessary and have been removed. Manifest: 31 424 -> 31 171 rows,
zero duplicate paths, 253 rows tagged `colobus_field_fp` all labelled
`Colobus_confuser` and all with a proven station.

Moving them out of `Background` into the dedicated confuser class is still the
right call, for the reason `config.SPECIES_FOLDERS` already gives, but it is a
relabelling of existing data and not an addition of new data. The paper says so.

| | |
|---|---|
| deployed baseline | 0.6953 |
| retrained, threshold fitted on the other fifteen stations | **0.9535** |

# Addendum, 2026-08-06: the class that describes the detector, not the forest

## What the detection run showed

The sixteen-fold numbers say the retrained head re-ranks V12's candidates well:
0.6953 -> 0.9535 macro precision. Running the same head over raw audio says
something else. Assembled as a whole model and turned loose on IPA4ST's daytime
recordings it produced 1 154 Cernic detections against V12's 131 in the same
window, and the first six checked by ear -- one per confidence band plus two
C_pogonias -- were all wrong, at confidences up to 0.988.

Six of six wrong at 0.988 looks more like a broken input path than a weak model,
so that was checked before anything was concluded. It is not broken: pushing the
same clips through the packing path and the detection path agrees 17 times out of
18, the one difference is the documented loudest-window-versus-first-window
choice, and the same waveform through both image builders is bit-identical.

The failure is real, and the cause is in the Background class. Measured on the
manifest before this session's change:

| source of Background | rows | share |
|---|---|---|
| the model's own false positives, or reviewed detections | 24 372 | 93 % |
| curated reference material | 1 951 | 7 % |

Even the 17 101 BirdNET clips inside that 93 % were chosen by a detector. So the
class does not mean "the forest"; it means "what a detector already reacted to".
A head trained against it separates calls from that narrow set, which is exactly
what re-ranking a candidate list requires and exactly what scanning a recording
does not: most of what a recording contains belongs to neither class it knows,
and it picks one confidently.

**The paper must describe this as a re-ranker, not a detector.** The existing
framing as a screening and triage tool is right; nothing anywhere should read as
detection performance.

## What was added

19 573 windows drawn uniformly at random from the deployment recordings, in
per-station subfolders so `possible_stations()` still holds a station out.
Verified fold by fold before training: no evaluated row and no same-station
random clip appears in any fold's training set, and each fold withholds its own
1 179-1 242 clips.

Screened first with the deployed grouped-argmax rule. 0.7 % of random windows
would produce a detection; those 132 are held in
`data/outputs/random_mine_suspect` for a person rather than trained as negatives,
because a random window can contain a real call and labelling it Background
teaches the model that a call is not a call.

That 0.7 % is also the first measurement this project has of how the detector
behaves on audio nobody selected, and the 132 are the cheapest route to the
recall figure the paper has never had.

Background: 26 323 -> 45 896. Manifest 30 994 -> 50 567.

## What was NOT added, and why

**Denoising.** Sagar et al. denoise focal recordings with spectral gating before
overlaying PAM background, and adding it looked obviously right. Three attempts,
all rejected on measurement rather than taste:

| attempt | RMS retained | roar-band share |
|---|---|---|
| noise profile from audio beside each pulse | 0.141 | 0.629 -> 0.559 |
| noise profile from the recording's quietest 1.5 s | 0.691 | 0.487 -> 0.415 |

If denoising removed background, the roar band's share of the clip would RISE.
It falls in both, so what is being removed includes the roar. The first attempt
has an obvious cause -- the inter-pulse gap is 0.57 s, so a one-second context
either side is mostly the neighbouring pulses -- but the second does not, and
tuning further without a criterion is guessing.

There is a criterion available: the nine field positive controls. Denoising will
be tested against those, separately, once this run gives a baseline. Adding it
now would have made this run's result unattributable, since the random-background
change is the intervention being measured.

**The 5 s clips.** Still out of the class; their pulses are in.

    合并                              51/55 = 92.7%  (Wilson 95%: 82.7-97.1)

**部署模型在这两站相差 24 个百分点,重训模型的高置信扫描精度相差 0.3 个百分点。**
四个错全部落在该档最低端(≈0.95),IPA4ST 本折拟合阈值 0.995 会把它们排除。

这是本项目第一个"扫描"而非"重排序"的精度数字。此前论文里写的
"六个用耳朵检查的全是错的"是旧模型旧数据的结论,已删除。

### Colobus:三次尝试

1. **单脉冲**(665 个):野外 9 个 clip 触发 2/9。
2. **bout,强制 ≥2 脉冲**(701 个):触发 **1/9**,IPA1ST 黎明 0 个检测。**失败**。
3. **混合**(775 连续切片 + 665 单脉冲 + 9 野外):本轮训练中。

失败原因由测量给出,不是推测。野外确认的 roar 与库内素材结构完全不同:

    同样硬切成 3 秒        脉冲数   单事件时长   发声占比
    野外 9 个                1       1.60 s      0.53
    库内素材                 2       0.39 s      0.42

事件时长差 4 倍。Richards & Wiley (1980) 的森林声传播结论解释了这一点:
**混响主要抹掉的正是高速率振幅调制**,一串 2 Hz 的脉冲传播一段距离后到达
时成为一段连续低鸣。bout 把"1.7 Hz 节奏"写进了类的定义,而野外不提供它。

结论:**"更完整的呼叫结构"不等于"更接近野外"。**

### 两个被推翻的自有结论

- **crest 因数不是干扰的判别器。** 我先用 IPA1ST 黎明的 clip 对比 IPA20ST 的
  clip,得出 31 vs 5.5 的"干净分离"。正确对照是**同一批录音的随机窗口**:
  中位 12.2,p90 34.3。阈值 15 保住 77% 干扰的同时误收 **42%** 普通森林音。
  高 crest 属于那些黎明录音,不属于干扰。自动挖掘方案作废。
- **BirdNET 那 16,826 个不是我们部署的音频。** 只有 8.6% 落在我们 11 个站点
  坐标上,12.1% 在 2021-02 部署期内,其余是同一项目在 2021-07、2022-01/02/06
  别的点位录的。论文数据表和相应段落已改。

### 修掉的泄漏:source_group 不认识切分后缀

`_WINDOW_SUFFIX_RE` 不匹配 `__pulse01` / `__chunk0012` / `__bout00_2p`,导致
同一段 roar 切出的 665 个 pulse 被当作 665 个独立录音,同一 roar 的两个脉冲
可分到内部验证切分两侧。修复后:665 pulse -> 207 组,775 chunk -> 170 组,
166 个共享源录音的 pulse 与 chunk 正确合并。不影响 LOSO 站点留出
(那走 possible_stations),影响的是内部验证准确率与阈值校准。

### 那 9 个野外 clip 已转为训练数据
