## The one behavioural change

`src/config.py` — `TIME_FILTER_START/END` **05:30-10:30 → 05:00-19:00**.

The old window was never validated against anything. It keeps 40.2 % of the
confirmed calls: a gate meant to remove false positives cheaply was discarding
three fifths of the recall it exists to protect. Swept over every (start, end)
pair at >= 95 % recall by `scripts/calibrate_time_gate.py`:

    gate off      6 189 detections, 2 535 calls, precision 0.4096
    05:00-19:00   3 571 detections, 2 503 calls, precision 0.7009
    dropped       2 618 detections,    32 calls, precision 0.0122

70.8 % of false positives removed for 1.3 % of calls. The removed mass is a
nocturnal insect chorus — hour 03 alone is 1 641 detections and zero calls.
IPA4ST, worst station in the deployment at 0.0405, scores 0.6947 gated: it was
never a bad station.

**Two things this obliges the manuscript to do**, both flagged in
`paper/SUBMISSION_CHECKLIST.md` (item reopened):
1. Every field figure currently in the paper was computed gate-OFF and nothing
   says so. State the regime or the validation section is unreproducible.
2. 32 confirmed calls fall outside the window. Any diel claim must be measured
   with the gate OFF, or it recovers the window that was imposed.

## Four correctness fixes

All in `scripts/train_v13_loso.py` unless noted. None change what is measured;
they change whether the measurement is right.

1. **Feature cache is written atomically.** `open_memmap` allocates the full
   25 GB before the first batch, so the old row-count check passed on a file
   that was correctly shaped and almost entirely zeros. This fired for real:
   an interrupted build produced a cache whose row 0 held data and rows 1000+
   were zero, and the next run printed `reusing` and would have trained on it.
   Now builds to `.partial` and `os.replace`s on completion.

2. **The deployed decision rule.** Scoring used `probs.argmax() == cernic`;
   deployment argmaxes over `config.DETECTION_GROUPS`, which folds
   `Colobus_confuser` into Background (`src/detection.py:236-241`). The old test
   is strictly weaker and biased one way — too generous. Measured cost on
   IPA20ST: `matched_fps_removed` 0.7419 → 0.6207, **12 points**.

3. **Time-gate-aware scoring.** New `gated_*` columns score each fold inside the
   deployed window. Without them the sweep credits V13 for rejecting the 2 618
   nocturnal windows the gate already discards for free. Detection times are
   joined from the review table's `timestamp` + `start_s`, **not parsed from the
   filename** — two filename schemes coexist and a regex matching one of them is
   how "90.7 % of Colobus detections are nocturnal" was computed from 97 of 253
   files. True value over all 253 is 48.6 %. Join resolves 6 189/6 189.

4. **Incremental CSV + saved head weights.** The sweep used to write once after
   all 16 folds and save no model at all, so `best_model_v13.h5` referenced at
   `HANDOFF.md:205` had no producer.

   **The saved heads are NOT deployable, and it is not just the missing trunk.**
   `train_v13_loso.py` orders its classes `sorted(index["label"].unique())` =
   `[Background, Cernic, Colobus_confuser, Colobus_guereza]`, while
   `config.CLASS_NAMES` — which `src/detection.py` uses to read the output — is
   `[Cernic, Colobus_guereza, Colobus_confuser, Background]`. Dropping a saved
   head into the detection path would read **Background as Cernic**. The sweep
   itself is unaffected: it indexes by name throughout
   (`class_names.index("Cernic")`, `DETECTION_GROUPS.get(name)`), never by a
   hardcoded position. But producing `best_model_v13.h5` means recomposing the
   frozen trunk *and* remapping the class order, which is why HANDOFF section 3d
   cannot run.

Plus `scripts/build_v13_dataset.py`: `DRIVE = "D:/"`, and a cross-drive fallback
for `os.path.relpath`, which raises on Windows when the clip is on D: and the
repo on C:.

## Three new scripts

- `scripts/calibrate_time_gate.py` — reproduces the window above.
- `scripts/calibrate_cleanup.py` — refits auto-cleanup against the 6 189 human
  verdicts, **leave-one-station-out**. `flag_isolated` is exactly
  `n_neighbours == 0`, i.e. a 0..58 count collapsed to one bit. Graded and
  stacked after the time gate it is monotone (precision 0.104 → 0.930 across
  the range) and its direction holds at 16/16 stations, because it is an
  unnormalised count and not a distance — which is why every earlier threshold
  died in LOSO (`scripts/rank_signals_experiment.py:4-6`). Held-out:

      no gate                       0.4096  recall 1.000
      time gate                     0.7009  recall 0.987
      + n_neighbours (LOSO fitted)  0.8690  recall 0.898, 90.6 % of FPs removed

  Order matters: isolation alone is 0.465. The insect chorus is the *densest*
  thing in the recording, not the most isolated — the gate has to go first.

- `scripts/reject_array_wide_events.py` — rejects detections firing across the
  array at once. 2021-02-24 15:00 is 71 detections across 9 stations; 19:30 is 66
  across 11. Those two half-hours are 54.2 % of every Colobus detection ever
  made. Stations are kilometres apart; that is a storm front.
  **Read its docstring before using it**: "a troop does not call at nine stations
  at once" is false for a chorusing species — 46.3 % of confirmed real Cernic
  calls sit in array-wide slots even at `--min-stations 6`. Guereza roars ARE a
  dawn chorus, so `--chorus-window 05:00-08:00` is mandatory for a guereza
  search or the rule deletes the signal it was built to find.

## Known and deliberately not fixed

- **The two Colobus classes take half the loss and are never evaluated.**
  `compute_class_weight("balanced")` gives one guereza clip ~34x the gradient of
  one Background clip, while `fold_masks` scores zero Colobus rows in all 16
  folds — every guereza clip is library audio with no station. Left alone on
  purpose: the deployed model is four-class, and changing the loss as well as
  the split and the backbone would make a V13-vs-V12 difference unattributable.
  **The two-class ablation is the natural next run.**
- **397 BirdNET clips are silently dropped**, in `Negative/` subfolders that the
  flat glob misses across 7 species. One is `afwowl1`, African Wood Owl, 200
  clips — nocturnal, low-frequency, pulsed, i.e. the exact confuser profile, and
  the one folder not in training. Fixing needs the image pack rebuilt.
- **V13 features are stock ImageNet; V12 fine-tuned** (1 972 740 trainable vs
  12 297 732). A V13 win is a valid one-sided result; a V13 deficit is not
  interpretable. Not fixable on this machine.
- `src/config.py:81` still lists `outputs/auto_cleanup/auto_flagged_fp` in
  `BACKGROUND_FOLDERS`, so a fresh dataset build loads 4 344 clips as Background
  with no user action — including the `mahal/` dump that audits 44/44 as real
  calls. `README.md:111-115` still instructs the loop that caused it.

## Species question — resolved differently than expected

Santi reports black colobus (*C. satanas*) at the site. But *C. guereza*'s range
**does** include Gabon, with *C. g. occidentalis* reported from NE Gabon
(Makokou/Belinga) — the site. *C. satanas*'s eastern limit is ~12 E and the
stations sit at 12.75 E. Both species are at a range edge here; the target is
plausibly correct, so the earlier "wrong species" hypothesis is **not**
supported. What remains true and unresolved: **no colobus vocalisation has ever
been confirmed at this site.** All 172 reference clips are Macaulay Library
(owner-confirmed), all 253 field detections were listened to and none is a roar,
and the 6 189-row review is 100 % Cernic. Presence is unestablished, and the
dawn-targeted search is the cheapest test.
